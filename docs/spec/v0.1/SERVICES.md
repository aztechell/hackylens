# Service contracts v0.1

Normative companion to [Architecture Specification](README.md). Time is required by Core; other extensions are individually declared. All inherit common ownership, deadline and error rules. Names denote semantic operations, not a fixed C ABI.

- S-TIME-01: Time returns monotonic microseconds in a boot-local domain. Deadline creation rejects overflow and excessive intervals. Sleep preserves distinct wake target and absolute operation deadline. Reached target wins; otherwise cancellation precedes expiry. Nonzero successful sleep observes progress; frozen/regressing clock fails. Declare maximum interval and check slice.
- S-INPUT-01: One logical state and event stream serves all clients. Accepted transitions include complete post-state, changed, pressed and released masks, sequence and acceptance timestamp. Pressed = changed AND state; released = changed AND NOT state. Holding does not repeat edges. Declare supported logical inputs, pulse-only inputs and sampling/debounce policy.
- S-INPUT-02: State reads do not consume events. Readers have independent cursors; open starts after current sequence. Empty read returns pending without waiting. Bounded history reports overflow with exact lost count and latest stable state, then resynchronizes without replay. Closing one reader does not affect others.
- S-LIGHT-01: Nonempty supported channel claims are atomic. Overlap fails busy; disjoint claims may coexist. Scalar and RGB components are integers 0..1000. Invalid values or unauthorized channels fail before effects.
- S-LIGHT-02: Ordinary close attempts safe-off and may retain claim for retry. Forced retirement attempts all channels with unchanged deadline, invalidates claim and quarantines unsafe channels locally.
- S-DISP-01: Declare dimensions, planes, formats, alignment, capacities and transfer/present bounds. Plane claims are exclusive per plane. Origin top-left, x right, y down, half-open rectangles, checked arithmetic. Zero-area or wholly clipped operations are no-ops. Partial blits preserve original stride and offset source by clipping delta. Null clip resets full bounds. RGB565 byte views, if supported, are big-endian.
- S-DISP-02: Transactions have explicit begin, commands/borrows, present or abort. Validation failure preserves staged state. Writable surface and command-batch modes are mutually exclusive in a native render pass. Borrows remain valid until terminal operation; retirement invalidates them and prevents unsafe reuse.
- S-RENDER-01: Native render extension requires runtime-owned transaction and callback-scoped surface. App cannot present, abort or claim a plane through the surface. Runtime aborts where possible and unwinds on callback/provider/present/budget failure. Busy display retains invalidation.
- S-RENDER-02: Bounded invalidation set coalesces identical rectangles and supports full redraw. Successful start schedules initial full redraw when render exists. Invalidation during render schedules another pass without waiting for next timer. Null render creates no competing transaction and render requests fail explicitly. Requests only in RUNNING callbacks.
- S-LINK-01: Modes sharing a connector share exclusive ownership. Declare supported modes and ranges. Claim authorizes only requested supported modes. Active operation blocks mode change; validate before routing effects and quiesce old mode before applying new. UART 8N1 and 7-bit I2C controller/target are optional subsets.
- S-LINK-02: Incremental transfers identify operation lifetime, declare capacities, preserve deadlines and expose partial progress/cancellation. Stale tokens cannot alias new operations after reopen. Forced retirement quiesces caller buffer access or prevents reuse, invalidates claim and quarantines unsafe connector. Failed ordinary close remains retryable.
- S-POWER-01: Off/restart are separate optional features. Preserve absolute deadline through pending preparation. Where applicable stop scripts and flush/unmount storage before hardware action. Preparation failure/expiry prevents action; returned hardware failure restores prior mount where possible.
- S-ACCEL-01: Read-only signed X/Y/Z in milli-g including gravity, declared axes. Initialization may return pending. Output updated only on success. Distinguish absent, unsupported and I/O failure. Optional motion status documents repeat/latch and orientation semantics.

Camera, vision, data and audio remain separately versioned services; their complete portable schemas are not frozen in v0.1. Common ownership, borrow, deadline and shared-provider rules apply when used by a claimed profile. No camera accuracy, storage atomicity, model format or audio latency guarantee is established here.
